# 跨模块故障排查

先记录实际主机、部署目录、提交与镜像、卡片 UUID、配置版本、当前任务和最后已确认结果。只读检查也要保留退出码；未知结果写未知，不用历史截图代替当前现场

## 现象、检查、判断和处理

| 现象 | 优先只读检查 | 判断 | 处理 |
| --- | --- | --- | --- |
| 网站部署成功，旧卡仍缺接口 | 卡片实际容器镜像、发布器版本和逐卡任务阶段 | 两业务服务更新不保证逐卡阶段运行 | 按[部署手册](deployment.md)核对新发布流程与固定目标，不批量重建 |
| 卡片 enabled，但 ERROR / pending | `status`、`configuration_pending`、期望/实际配置版本、配置错误 | enabled 是用户意愿，不代表可路由 | 查[环境](modules/environments.md)与[设置](modules/settings-plugins.md)，不要强写 READY |
| 认证文件列表出现两个条目 | 当前绑定文件、真实文件数、内部身份目录、CPA 源码与补丁身份 | 可能是内部身份文件误枚举，也可能真的多凭据 | 先确认分类与运行版本，按[凭据手册](modules/credentials.md)处理，不能盲删或重新导入 |
| managed-identity 200，fallback 404 | 两个接口分别的未认证/已认证响应、镜像 digest | 一个能力存在不代表另一个存在 | 需要兼容运行时，不能当 Token 已失效而反复刷新 |
| “上游认证失效” | 凭据是否被撤销、错误范围、模型成功证据、CPA 与 Manager 状态 | 聚合错误、单模型失败、真撤销须分开 | 保留现场，按[额度](modules/quota.md)及[凭据](modules/credentials.md)验证；不要重置额度试运气 |
| 有模型列表但推理失败 | 实际模型准入、额度/冷却、唯一凭据、出站与真实请求日志 | 列表不是模型调用证明 | 单独授权最小真实请求，按请求 ID 对齐日志 |
| 逐卡停在 draining | 持久门禁、未过期租约、请求超时和结算日志 | 新请求已阻断；旧请求可能仍在进行 | 等待或查结算；不可持环境行锁等待，也不可先停容器 |
| switching 后服务重启 | 同一 release/digest 的断点、受保护原始备份、实际容器镜像 | compose 可能已写新、容器仍旧，或容器已新但尚未验证 | 按原版本续跑，不换目标，不回放旧认证卷 |
| 代理保存成功但仍连接失败 | 实际监听器、单卡 proxy_url、前置是否配置/存在、ISP 探测结果 | 入站路由和出站是两层；已配置失效前置不能静默绕过 | 查[代理手册](modules/proxies.md)，不关闭隔离或暴露控制端口 |
| 额度未知、零额度或冷却残留 | 来源、观测时间、窗口重置点、每模型额度及独立运行时冷却 | 未知不是零，也不是可用；整卡与模型冷却不同 | 按[恢复手册](modules/quota.md)查询原操作及证据，避免重复兑换 |
| 前端展示旧状态 | API 返回、权限、查询键、版本、保存结果与缓存失效 | 可能是缓存，也可能后台未完成 | 先查 [Dashboard/API](modules/dashboard-api.md)，不只靠刷新页面判成功 |
| 反馈 CLI 连接失败或 401 | API 根地址、token 有效期、TLS、退出码 | 无法连接不等于没有反馈 | 明确报错，按[共享反馈工作流](../FEEDBACK_WORKFLOW.md)恢复授权，不改全局身份 |

## 只读健康检查的限度

健康检查命令按[统一更新手册](../../deploy/UPDATE_RUNBOOK.md)在实际业务容器中执行，不能假设宿主机暴露了 4000/8091。`releasectl.py status` 需要在实际部署目录和已授权的发布服务连接上运行；任何连接失败都保留为失败

当网页终端断开，先确认任务是否已持久化及是否仍在执行，复用原连接恢复后读取状态。不要因为终端断开就再次提交有副作用的操作，也不要把本地 Codex/代理错误当成服务器上游认证结论

## 恢复前的停手条件

缺少当前运行身份、备份、兼容结论、唯一凭据或明确操作授权时，不换镜像、不重置、不刷新 Token，不清理卷和数据库。镜像回退只恢复已核验的旧镜像与运行状态；数据恢复另走[备份边界](data-and-backups.md)

恢复报告必须写清“哪个卡片、哪个模型、哪次真实调用”通过，其他范围仍未验证。复现及本地修复通过、commit、push、构建、部署和线上恢复分别记账
