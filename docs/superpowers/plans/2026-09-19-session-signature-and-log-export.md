# 会话签名与日志改动说明

同一客户端会话复用 LiteLLM 原生部署亲和性，以虚拟密钥隔离绑定。支持会话请求头、Claude metadata.user_id 的 JSON 和旧格式，以及 Codex prompt_cache_key。默认开启号池会话亲和性，已有明确关闭的设置继续保留，可在路由设置中开启。绑定超过有效期或缓存丢失后，不能保证找到原卡片

CLIProxyAPI 卡片通过 LiteLLM 已有的 supported_endpoints 能力声明接收原生 /v1/messages，保留思考块、工具块和 Claude 会话信息。内部会话标识按虚拟密钥隔离，并保留 Claude 子代理标识。已有 CLIProxyAPI 会话亲和性在设置同步时启用，仍关闭内层重复重试。普通 OpenAI 兼容提供商不增加原生 Messages 声明，也不重写客户端会话头

带签名的历史不能自动跨卡重试或跨模型组兜底。原卡不可用时返回明确错误。只有完整文本历史、没有工具和上游状态引用、还未输出内容，且上游明确拒绝旧签名时，才在同一卡片清理旧思考状态后再试一次。不会生成签名，也不会恢复其他中转站的隐藏状态。日志保留原始请求，并以 signature_recovery 标记恢复，恢复成功的计价仍沿用当前成本处理流程

运行日志以费用（USD）替换缓存写入列。运行日志和完整日志显示总条数、页数、跳页和每页条数。费用未知继续显示未知，零费用显示零，不改变模型价格或历史费用

完整日志按提示词、用户、模型、思考和工具调用展示，可切换本轮与完整上下文。支持单条或整段会话导出 Markdown、结构化 JSONL 和原始 JSON，整段会话导出读取全部分页，并保留虚拟密钥筛选。读取失败不生成残缺文件，超过 64 MiB 需缩小范围

JSONL 为 conversation-v1，每行对应一次请求，包含完整上下文、模型输出、工具、请求标识、尝试次数、用量、费用和检查标记。它是蒸馏整理格式，需要转换为目标训练平台要求的格式。失败、截断、附件、脱敏、隐藏推理和 WebSocket 多轮记录需人工筛选；原始 JSON 可用于重新解析协议。不会解密上游推理，也不会把占位说明当作真实思考文本

本次不修改数据库表结构，不恢复或重写历史数据。上线时应更新网关和管理服务两份镜像，刷新部署能力并同步卡片配置后，再使用虚拟密钥验证原生 Messages、Responses、多轮工具和流式中断。新默认值不会覆盖管理员已保存的关闭设置

本地验证覆盖网关转发、签名恢复次数、输出后禁止重放、Claude 工具块、Responses 加密历史、原生亲和性、设置同步、分页与导出。浏览器使用示例数据检查会话卡片、完整上下文和跳页。仓库全量 TypeScript 检查存在无关历史错误；本次修改的生产前端文件通过类型检查与 ESLint 错误检查。当前未进行生产部署或真实上游端到端验收
