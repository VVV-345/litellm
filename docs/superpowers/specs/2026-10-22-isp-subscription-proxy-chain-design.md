# ISP 订阅与机场前置代理链设计

## 目标

允许管理员导入一个 ISP Clash 订阅，将订阅中的 Mihomo 出站节点作为 ISP 候选，并保留当前手动 ISP 导入。每个代理网关单独选择一个 ISP 节点和一个机场节点作为前置。LiteLLM 的 GPT 请求先通过机场连接 ISP 代理，再由 ISP 访问 OpenAI；OpenAI 看到的最终出口仍是 ISP。

当任一代理链路不可用时，网关必须拒绝该路径的请求，不得回退到直连或绕过 ISP 的机场节点。机场订阅继续沿用现有代理配置档案与节点选择功能。

## 管理流程

代理管理页面在现有 ISP 面板增加一个 ISP 订阅入口。管理员提交一个公网 HTTP(S) 订阅 URL 后，可导入或手动刷新。订阅响应必须是有效 YAML 对象，首版只读取顶层 `proxies`，不解析 `proxy-providers`。每个出站节点必须有唯一名称和有效类型；整份节点配置保留，不能把节点降级成仅有主机、端口及用户名密码的通用代理。

ISP 列表合并手动档案和订阅档案，并明确显示来源及节点类型。只有手动档案可以继续使用现有的协议、地址、凭据和有效期编辑器；订阅档案由订阅刷新维护。节点稳定标识按订阅节点名生成，重复节点名使本次导入失败，避免歧义绑定。刷新时更新仍存在的节点，将消失节点标记为不可用并保留记录和绑定；同名节点恢复时复用原标识。不会自动选择运营商或替换绑定。

每个网关行保留 ISP 选择，并在已选择 ISP 时单独显示机场前置节点选择。ISP 和前置节点分别持久化，因而两个网关可以共用一个 ISP 节点而使用不同机场。ISP 订阅导入、刷新、机场配置更新、节点选择和链路检测均为管理员操作。

## 代理链路

每个网关有两个 Mihomo 选择组：既有网关组负责将网关流量送入 ISP 链路节点，新增的网关前置组选择机场节点。生成的 ISP 链路节点复制手动 ISP 的现有 Mihomo 表达，或完整复制订阅中的节点配置，然后将 `dialer-proxy` 强制设为该网关的前置选择组。网关组在 ISP 模式下只允许该网关专属 ISP 链路节点和 `REJECT`，防止同一 ISP 档案被多个网关复用时节点状态互相覆盖，也防止机场节点成为意外的最终出口。

可选前置只允许配置中原有的实际机场出站节点，不包括其他网关生成的 ISP 节点或选择组。每个网关的链路节点和前置选择组使用独立名称。移除网关时同时移除该网关的链路节点、前置选择组和持久化选择。

订阅配置替换和普通机场配置更新必须保留所有注册网关组、前置组和仍有效的 ISP 链路节点。选择或绑定操作更新配置并重载 Mihomo；失败时恢复原配置并重载恢复版本。启动对账和订阅刷新遵循同一失效策略：绑定 ISP 不存在或被禁用时，网关组切至 `REJECT`。

## 存储和接口

现有手动 ISP 档案表、凭据加密格式和端口绑定表保持兼容。新增 schema 表用于单个 ISP 订阅元数据、订阅节点完整配置及来源专用绑定；另以端口为键保存每网关前置节点名。订阅 URL 和完整节点配置用现有 `StateCipher` 加密。订阅节点通过统一的 ISP 目录视图与手动档案共存，统一使用现有 ISP 绑定操作和网关档案 ID。内部领域类型区分手动档案与 Mihomo 节点，公开目录视图带来源标记；秘密和完整节点配置不通过 API 回传。

新增 Manager 接口用于导入/刷新 ISP 订阅及选择网关前置；新增链路探测接口绑定到具体网关。LiteLLM 管理接口保留现有管理员鉴权，前端 API 类型由 OpenAPI 生成。旧 API 路径、手动 ISP 导入、档案编辑、有效期和现有端口行为保持兼容。

订阅 URL 沿用现有公网 HTTP(S) 校验，禁止凭据、私网目标及重定向；请求不信任进程代理环境变量，且限制响应字节数和超时。订阅 URL、节点凭据、完整配置和上游错误响应不得写入日志或 API 错误正文。

## 链路检测

检测作用于实际网关端口，先请求出口 IP 服务，再请求 `https://api.openai.com/v1/models`。返回出口 IP 及位置/运营商识别结果，并显示 OpenAI 的 HTTP 状态或网络/超时失败。无 OpenAI API Key 的检测只能证明该链路可以到达 OpenAI API 主机；HTTP 401 视为主机和 TLS 连接成功，不能宣称完成了带账号的模型调用或证明账号具备服务资格。探测必须经过已选 ISP 与其机场前置，不允许由探测客户端直连绕过 Mihomo。

## 数据升级与回退

新增 Manager 表均通过幂等 `CREATE TABLE IF NOT EXISTS` 建立，不重写已有业务行，也不改变 Prisma schema。发布兼容性校验仅接受明确登记的附加表契约。旧手动 ISP 绑定由现有表继续承载；统一目录视图在读取时合并来源专用表，移除 ISP 绑定时清理对应来源的绑定。新版本回退后，旧代码忽略新增表即可继续读取既有机场和手动 ISP 数据。

## 验证

- 订阅解析接受有效顶层 `proxies`，拒绝空列表、重复名称、非法 YAML、损坏节点及过大响应；不读取嵌套 provider。
- 刷新保留同名节点 ID 和绑定，更新完整配置；消失节点被禁用、关联网关进入 `REJECT`；同名恢复能复用 ID。
- 多网关绑定同一 ISP 时分别生成独立链路节点和前置选择组；更换一个网关的机场不影响另一个网关。
- 验证订阅节点协议字段和认证配置完整保留，生成时只覆盖其 `name` 与 `dialer-proxy`；拒绝将管理生成的 ISP 链路作为前置。
- 验证配置重载失败时恢复原文件和运行配置；启动重对账、机场订阅刷新、网关删除及数据库写入失败均保持安全状态。
- 链路探测确认所有请求使用实际网关代理端口，并区分 IP/运营商探测失败、OpenAI 网络失败、超时及可达的 HTTP 认证响应。
- 验证旧手动导入/编辑/删除/绑定流程、Manager API、LiteLLM 鉴权转发、生成的 OpenAPI 前端类型和 ISP 管理页面。
- 运行对应 Manager、LiteLLM 管理端和 Dashboard 定向测试；真实部署验收另行检查出口 IP 与 ISP 所属运营商，并使用实际 GPT API 凭据验证模型请求。

## 不在首版范围

- 多个 ISP 订阅源、从 `proxy-providers` 递归导入及自动定时刷新。
- 自动按运营商识别结果绑定 ISP，或订阅更新后自动切换到其他节点。
- 机场作为最终出口、绕过 ISP 直连、跨账号网络代理链及新的代理内核实现。
- 无凭据的链路检测代表成功调用 GPT 模型。
