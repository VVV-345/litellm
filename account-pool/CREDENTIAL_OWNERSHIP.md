# 卡片与凭证一对一及清理记录

2026-09-16：在认证文件刷新、仪表盘配额刷新和逐次请求缓存率修复之后，增加凭证独占归属、删除互斥及账号辨识。原有提交和验证记录保留

每张卡片只能使用自身凭证。OpenAI 兼容卡片创建时只接受一个 API Key，已有卡片不能追加 Key。策略不能绑定或优先使用其他卡片，旧策略中的跨卡片绑定也不会参与路由

CLIProxyAPI 卡片要求容器内只有一个认证文件，并核对当前绑定文件。上传替换会先阻止新请求进入、取消旧授权会话，再移除旧文件和残留文件，上传并验证新文件。多个文件、缺失绑定或重复账号会阻止卡片接单；重新启用也必须重新验证归属

归属根据刷新令牌、API Key、服务账号私钥及凭证提供的邮箱、账号标识生成 HMAC 指纹，使用现有 secret seed 派生独立密钥。数据库只保存不可逆指纹及卡片 ID，不保存这些令牌或密钥的明文。邮箱和账号标识用于认证文件列表展示。仅提供 API Key 的上游通常无法返回个人账号，界面展示上游地址

生产环境通过 PostgreSQL 事务保证一组指纹只能由一个卡片领取，并以卡片 ID 的事务级 advisory lock 串行化刷新、上传、重新授权、配置和删除。进程内继续使用环境锁；额度接口仍按前次修复顺序调用。不同卡片只有在归属独立时才能并发执行

先删除凭证时，卡片保留并停止接单，取消尚未结束的 OAuth 会话，删除容器中的所有认证文件并重新确认列表为空。持久化清空绑定成功后才释放归属。上游清理失败或保存版本冲突会返回失败并保留归属，可以重试。不会把失败清理当作成功，也不会由等待锁的旧刷新任务重新创建已删除卡片

先删除卡片时，沿用既有分阶段清理，先禁用路由，再删除 Compose 资源、认证卷及目录，删除卡片记录后释放凭证归属。清理失败保留删除进度供重试。既有请求日志保留

令牌轮换或替换上传不会自动释放历史指纹。需要把旧账号转移给另一张卡片时，先明确删除原卡片的凭证，或删除原卡片并确认成功，再在目标卡片授权。这会同时清除该卡片当前凭证，请先确认要迁移的账号

启动及认证文件刷新会核验已有绑定。旧重复凭证、多个认证文件和多个 API Key 不会自动挑选后继续混用，需要明确清理后恢复。无法从旧凭证读取身份时也不会猜测归属，需要重新上传或重新创建该凭证卡片。认证文件列表展示卡片名、邮箱、账号标识、文件名和错误；未返回身份信息时显示尚未同步的提示

验证覆盖并发领取、轮换令牌后的重复账号识别、跨供应商同密钥拦截、删除锁、清理失败保留归属、删除前后版本冲突、重复启用拦截、替换清理顺序、禁止跨卡片路由及账号展示。测试使用内存归属实现和 HTTP 模拟，当前机器 Docker daemon 未运行，尚未执行真实 PostgreSQL 多进程竞争及 CLIProxyAPI 容器联调
