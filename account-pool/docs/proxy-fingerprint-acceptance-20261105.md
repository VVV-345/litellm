## 行为与兼容性

- 新指纹可选择 Linux、Windows、macOS；这是浏览器呈现的系统，worker 容器仍运行 Linux。保留手动语言模式，新配置默认按代理出口自动匹配。
- 自动模式在账号首次绑定时，通过所选代理查询公开出口 IP，再核对同 IP 的国家与 IANA 时区；语言由固定 Camoufox 0.5.9 SDK 的地区数据生成。代理失败、地区不明或时区无效时拒绝绑定，不切直连，不开始登录。
- 最终系统、语言、时区、指纹及摘要一起保存。相同账号重试复用原配置；已有配置缺少新字段时按 Linux、手动模式解释，不静默重新生成或覆盖。系统及匹配模式不可在已有配置上修改。

- 预装并保留固定浏览器归档中的 Linux、Windows、macOS 字体；不在登录时下载资源。保留只读容器、固定 digest、网络隔离与原有输入门禁。

## 刷新凭据、额度重置与 access 降级复查

本轮未更改这三条业务流程，没有读取或刷新生产凭据，没有消费生产重置券，也没有对生产 Key 做新调用。

- 对当前 Manager 的凭据刷新、额度重置传输/服务/API、access 降级重新执行回归，74 项通过。
- 在先前由当前适配补丁建立的固定 CPA 源码副本，重新运行 `internal/auth/codex`、`sdk/cliproxy/auth`、`internal/api/handlers/management` 三个包测试，全部通过。
- 故障注入重新覆盖请求中断、502、成功响应损坏/缺失 access token，以及刷新结果未知后重启；不继续重放同一个旧 refresh token。额度恢复失败不触发刷新，也不擅自解除限制。
- 额度重置只读绑定凭据，使用实际 access token，而不是会隐式续期的 `$TOKEN$`；兑换结果不明确时只核对原兑换身份，不当作成功或再次消费。
- access 降级默认开启，已有手动关闭保留；同卡同模型有成功推理证据才放行。额度观测暂不可用不单独否定成功推理，但不能绕过已知额度耗尽、冷却、停用或账号权限。

不能保证上游刷新永远成功：如果上游已将 A 轮换为 B、作废 A，而 B 的响应丢失，客户端无法凭空恢复 B。当前补丁会暂停重放 A；仍有效且实际可调用的 access token 可以继续降级，access token 失效后仍需重新授权。旧 CPA 镜像不一定包含这些保护；本轮本地结果不证明生产卡已升级或现在可调用。
